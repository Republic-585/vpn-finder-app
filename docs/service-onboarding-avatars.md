# Добавление VPN-сервиса в каталог

## Обязательное правило

Новый сервис должен отображаться в Mini App с корректными данными и собственным аватаром. Не активируйте запись, пока не заполнены и не проверены все необходимые поля.

### Данные сервиса

Перед переводом записи в `active` проверьте:
- уникальный `id` формата `VPN-NNN`;
- корректные `name` и `slug`;
- рабочую `referral_url` (проверить переход вручную);
- `description`, цену и валюту, если они применимы;
- тарифы, лимиты, платформы и возможности — только подтверждённые провайдером данные;
- `sort_order` и остальные поля, которые использует карточка каталога.

Не подставляйте вымышленные тарифы, функции или лимиты.

### Аватар

1. Получите оригинальный логотип сервиса.
2. Предпочтительно укажите прямой HTTPS URL файла изображения в `logo_url`.
3. Если прямого файла нет, укажите официальную страницу бота/сервиса в `bot_url` или `source_urls`, где можно обнаружить оригинальный логотип.
4. Не используйте случайные CDN, скриншоты чужих карточек, текстовые заглушки или логотип другого сервиса.
5. После добавления/обновления записи запустите GitHub Actions → **Mirror service avatars** → **Run workflow**. Автоматическая проверка также запускается каждый час.
6. Дождитесь успешного завершения шага **Download and validate every active avatar** и проверьте, что для нового ID появился файл в `assets/avatars/` и запись в `manifest.json`.
7. Убедитесь, что workflow опубликовал изменения в `main`, GitHub Pages обновился, а изображение открывается по адресу сайта.
8. Только после этого считайте аватар и сервис готовыми к полноценной публикации.

## Что делает автоматизация

Скрипт `scripts/sync-avatars.mjs` получает все активные сервисы из Supabase, проверяет источники, скачивает изображение, проверяет тип и размер файла, сохраняет локальную копию с именем по ID сервиса и обновляет локальный manifest. Workflow запускается каждый час, вручную и при изменении самого механизма.

Если у нового активного сервиса нет доступного оригинального изображения, проверка должна завершиться ошибкой: это сигнал исправить исходные данные, а не повод считать сервис полностью оформленным.

## Важно

- Не меняйте ID уже существующего сервиса после создания локального аватара.
- Не удаляйте и не переименовывайте локальные файлы вручную.
- Не изменяйте партнёрские ссылки без отдельной проверки.
- Не считайте generic fallback `assets/avatars/default.svg` полноценным логотипом. Это только аварийная защита интерфейса.
